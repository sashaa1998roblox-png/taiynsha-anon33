TAIYNSHA — ЭТАП 1: АВАТАРЫ И АУДИТ
==================================

В этом этапе:
- Удалён выбор символических/геометрических аватарок.
- Оставлена загрузка фотографии профиля.
- Если фото нет, отображается стандартная серая заглушка-силуэт.
- Сохранена текущая визуальная структура сайта.

ВАЖНО: это промежуточная версия, а не готовая публичная соцсеть.

Что обнаружено в исходном проекте:
- Профили и пароли хранятся в localStorage конкретного браузера.
- Пароль хешируется SHA-256 на клиенте; это не серверная авторизация.
- Профили не общие между устройствами.
- Общая лента целиком перезаписывает один JSON-объект Netlify Blobs.
  При параллельных изменениях возможна потеря обновлений.
- Админ-права выдаются по совпадению юзернейма в браузере и не защищены сервером.
- Фото сейчас сохраняется как Data URL в локальном профиле, не в общем облачном хранилище.

Следующий обязательный этап — подключение Supabase:
1. Supabase Auth для регистрации и входа по уникальному username + паролю.
2. PostgreSQL для профилей, публикаций, лайков, просмотров и жалоб.
3. Supabase Storage для аватаров и фотографий постов.
4. Realtime для появления новых публикаций без обновления страницы.
5. Row Level Security (RLS) и серверные роли для защиты действий и админки.

Для следующего этапа нужен проект Supabase. Создай бесплатный проект на
https://supabase.com/dashboard и пришли Project URL и anon/publishable key.
Это публичный ключ клиента, его можно использовать на сайте при включённой RLS.
НИКОГДА не присылай service_role key, пароль базы данных или другие секреты.

После подключения нужно будет перенести существующий интерфейс с локального
хранения на сервер. До этого не используй промежуточную версию как готовую
публичную сеть с реальными аккаунтами.
